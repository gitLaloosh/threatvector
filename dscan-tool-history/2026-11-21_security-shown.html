Why

  • The map's table stored each system's security rounded to 3 decimals, then to hundredths, and the page rounded that again to tenths. Measured 2026-11-20 against ESI's unrounded values, 333 systems showed a tenth the game doesn't (Jita 1.0 for 0.9, Juddi 0.7 for 0.6, XQS-GZ −0.5 for −0.6). 058 had fixed only the 0.45 line (LESSON #170).
  • The rule the game uses was checked in game by the owner on 10 systems: the nearest tenth of CCP's unrounded value, and anything above 0.0 and below 0.05 shows 0.1. The two systems on a halfway point (A2V6-6, A-5M31) show the nearest too.
  • The owner's picks: system names coloured from the table, "Read the table (Recommended)"; "Two PRs (Recommended)"; "No mockup (Recommended)"; at the build review, an unchecked halfway value flagged rather than failing the run ("yes, the second.").
  • Also in this delivery, flagged by the owner for the next one: "wormholes tab, setting two systems as "Home" results in odd behavior. particularly related to the routes." His fix: "Only one Home: setting Home on a system clears it from the other, with a line saying so.", "do not overwrite the existing home.", "pick the closest one and remove the other(s)", and at the review "2. yes to both, 3. sure, 4. sure."

What changed

  • The generator (tools/jump_table_update.py): INTEL_MAP.secT, int8 tenths, the tenth the game shows (shown_tenth), in place of sec and band; it asserts for every system that the shown tenth's band is the unrounded value's. A value on a halfway point (within 5e-6, so it reads x.x5000 at five decimals) takes SEC_CHECKED_IN_GAME (A2V6-6 −0.9, A-5M31 −0.2), else the nearest tenth, named at the top of the pull request to check in game. The pull request lists the systems checked in game with CCP's value, and every system whose shown security changes. --self-test runs the rule's cases.
  • Two pull requests. This one leaves the page's table as it is, so the page looks the same: itMapSecT returns secT when the table has it, and otherwise reads sec + band as 058 did (the fallback). After the merge the "Jump table" workflow (twice a day, or by hand from Actions) opens the data pull request; the next page delivery after that one removes the fallback.
  • The page: itMapTable decodes secT; itRpBand takes the band from the shown tenth; k-space system names take their tenth from the table (itSecTab), at once and with no ESI request, and ESI is asked only for J-space and systems the table doesn't hold. Nothing on the page rounds security any more once the data is in.
  • One Home: setting Home clears it from every other system, with the line "<new>: Home. <old> is no longer Home."; an import never replaces your Home; with none of yours, a shared chain's Homes are taken and the closest kept; two or more already saved (an older page) are settled once where you are is known: the fewest jumps by the Routes panel's own neighbours (gates, your holes, the bridges in use) keeps it, a tie or none reachable the lowest system ID, with a line (shown when the tab is next drawn if it isn't now). Only st is cleared in tvWhMarks, in the same form.
  • Checks: check_sec_shown.py for both forms (10 systems pinned with secT; mutants on a copy given a made-up secT); check_jump_table_update.py converts a page from before 063 first and runs its cases on the converted copy; intel_map_look_check, intel_map_stack_check and route_planner_check read either form; the four security-reading page checks also run on a made-up secT copy. New: wormhole_home_check.py (one Home, and names from the table), with six mutants.
  • Info text: checked; none changed. Stored browser data: tvWhMarks keeps its form (only a second Home's st is removed): safe both ways. Page size: source 1,019,212 bytes gzipped, served 646,650 (main: 1,017,726 / 645,967).

Lesson for future models

  • LESSON #170 holds, and this is its root fix: store the value people see, worked out once from the unrounded source, rather than a rounded value every reader rounds again. Where a rule can't settle a case from the data (a value on a halfway point), keep what was seen in the game beside the rule, and make anything new in that case visible to the owner rather than guessed silently.
  • When a plan gives one threshold in two forms, check both against the cases it names before choosing: here one form missed a system the plan relied on and the other caught two it meant to leave alone.
