Checks picked against main

Tools 2026-11-08 · page unchanged (after v2026.11.08.3)

Why

  • Building 026, run_checks.py --auto ran only the lints: with no --since the picker compared with the last commit, and the work was already committed, so it saw no change. Rerun against a copy of main, it picked 82 page checks and one found a real bug.
  • A fresh build session's dry run showed the other side: a one-line comment in an Intel function picked every area, because the CSP meta's script hash (line 6) changes with every edit to the page and counted as a change to every area.
  • The owner: "make it your first priority - these deliveries have been taking forever."

What changed (tools only)

  • Compared with main: with a .git folder, the picker compares with where the branch left main (git merge-base HEAD origin/main; origin/main itself in a shallow clone), committed work included, and the run says what it compared with. With no origin/main it warns that it fell back to the last commit.
  • The CSP hash alone isn't a change: a line that differs only in the script hash counts as nothing; a change to the policy itself still runs every page check.
  • Never-delivered files don't count: git-ignored *.local.* files (the names list) and _site/.
  • Files that picked everything for no reason: the HTML-sink baseline, csp_hash.py and the publish step are lints (fast); the site's icons, render_icons.py and CNAME go to the layout checks.
  • A .git file (a git worktree) is accepted as well as a folder. CLAUDE.md says --auto alone works again (after git fetch origin).
