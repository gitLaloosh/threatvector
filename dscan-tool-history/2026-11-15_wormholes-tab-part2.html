The Wormholes tab, part 2: the system menu (and the empty map's height)

Wormholes 2026-11-15 · v2026.11.15.2 · build queue 051 · plan roadmap/wormhole-mapping-plan.md ("Build in parts" 2, D25, D26, D34) · mockup Claude outputs/wormholes_tab_mockup.html

Why

The owner's requirements for the chain map: borders "set by the user to denote level of danger", a lock "to prevent accidental deletions of home systems for example" ("LOCK is all we need"), tags, copy the name, remove, from a menu on each system. At the build review he picked the page's own tag look for the tag on the map ("the page's"), and from the live site: "the map should push the bottom of the page to the bottom of the screen even if it's empty. no re-size when it's populated that way."

What changed

  • The system menu: right-click a system on the Wormholes map, or press and hold on a phone. A menu (no close button: Esc, a press outside or a pick closes it; focus on its first item, the arrows move): the six statuses and No status, a tag (up to 8), Lock (can't be moved or removed) / Unlock, Copy the name, Remove from the map (greyed with "(unlock first)" while locked). A right-click on empty space still opens "Add a system here". "Routes from here" waits for the Routes panel (part 4).
  • Status as the box's border, in six new colour tokens (--wh-st-*); named in the menu, the System panel (the page's tag) and the box's hover, which is new (written only when the box under the pointer changes).
  • Tag on the box in the page's tag look (a faint fill in the status colour, its text in that colour); in the System panel too.
  • Lock: a locked system isn't moved by a drag (alone or in a group: the others move), Rearrange leaves it, and Remove refuses it in the menu and the System panel with "<system> is locked: it can't be moved or removed until you unlock it." A connection touching it can still be deleted.
  • Copy the name: to the clipboard, or, when the browser refuses, the name stays in the menu, selected, to copy by hand.
  • The empty map is as tall as the full one, to the bottom of the screen; adding the first system resizes nothing. Part 1 worked the height out only after the empty map had returned, so the empty box was 320 px.
  • The whmap info panel and its colour key (the statuses and the lock); the settings popover says Rearrange keeps locked systems.

Stored data

A new key, tvWhMarks {v: 1, sys: {id: {st, tag, lock, at}}}: part 1's reader rebuilds each system in tvWhChain from the fields it knows, so a part-1 page in another tab, or a revert, would have dropped them there. at is a locked system's place, so an older page's Rearrange (which clears tvWhChain.pos) can't move it. Entries for systems no longer on the map are dropped on read. tvWhChain keeps its form. Both ways: the new page reads what part 1 wrote (no tvWhMarks: no marks); part 1 reads tvWhChain as before and never touches tvWhMarks (checked with main's page in the same browser). The limit: an older page doesn't know about locks, so it can still remove a locked system.

Checks

  • tools/page_checks/wormhole_menu_check.py (new): the empty map's height at 1440 and 390 px; the menu by right-click and by press and hold (real touch events, start to release); statuses read off the canvas, the System panel and the hover, kept after a reload; the tag cut to 8; Lock against a drag, a group drag, Rearrange and both Removes; Copy, allowed and refused; main's page saving the chain; 8 mutants.

Known limit: Rearrange lays the other systems out as a tree around a locked one, which keeps its place, so a box can land on top of it (the menu and the System panel still reach it).

Page size: source 927,134 bytes; served 587,311 bytes (gzip -9).

Lesson for future models

LESSON #167: a press and hold that opens a menu under the finger is clicked when the finger lifts. The browser sends its mouse events and a click after a touch to the same point, where the menu's first item now is: every hold set the status "Home" and closed the menu. The mockup's test opened the menu by script and never lifted a finger. Cancel that touch's touchend when the hold opened something, and test a long press with real touch events from start to release.
