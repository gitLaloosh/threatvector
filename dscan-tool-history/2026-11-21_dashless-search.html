System names found without their "-"; three Intel bugs in J-space

PageIntelSystem AnalyzerWormholes 2026-11-21 · v2026.11.21.2 · build queue 064 · plan: roadmap/dashless-search-plan.md · no mockup (the owner's choice)

Why

  • The owner, 2026-11-16: "system search in intel map should be searchable without "-" and still hit. test for any conflicts if done this way.", widened on 2026-11-20: "(should be the case in all system searches for all tabs)". His answers to the plan's questions: "1. just the feed search box, 2. your recommendation, 3. no mockup." The count over the page's own name lists found no two systems sharing a dashless form (5,268 k-space and 2,604 J-space names).
  • Three bugs from his screenshot in a J-space system whose way in wasn't known, flagged for the delivery after 063: "left panel bug" (the map's filter column in 4 columns of 3 rows), the status line naming the system by its ID, and "Your system isn't known yet" while the system was known. At the review: "With the Wormholes tab hint (Recommended)" for the new line, "Yes, same wording (Recommended)" for the System Analyzer's line, "Yes, build it".

What changed

  • One helper for every box (sysFind, sysSuggest, sysManyText; the dashless forms built once per name load, sysFlatK / sysFlatJ): a query with a "-" matches exactly as before; one without is compared with each name's dashless form ("1dq1a" is 1DQ1-A). A form two systems share is never picked; the box lists them and asks for the dash. Each box asks for its own kind of system: 'k' (stargates) for the Intel map's search, Routes → Avoid, Intel's Wormholes list → Add, the "word = system" list and the System Analyzer; 'all' (J-space too) for the Wormholes tab's + Add, "Add a system here" and its Routes pin. So J-space names never fill a stargate-only list (the plan had them in one shared list; found at the review). whIdOf stays exact: it also reads the Local log's names.
  • The Feed search: a query without a "-" also meets each system's dashless name (itSearchText(e, flat)); a query with one sees the text exactly as before. Pasted Sov and jump bridge lists and Intel's reading of chat lines are unchanged.
  • The System Analyzer's typed box: the browser's <datalist> is gone; it uses the map search's own list. The map search's combobox is now sysComboBind, shared by both (rows, keys, a press); the System Analyzer's rows show the system and its region, its list in the flow under the box so the ⚙ panel never cuts it off. On a phone both lists' rows are 44 px.
  • No map, only its message (the "left panel bug"): while your system isn't known, the map box gets nomap and shows only its message, with no filter column, canvas, search, zoom or rail, and Near You is hidden; all come back with the map. The filter column had been laid out for a map of height 0. Also found: itm.cv.hidden never hid the canvas (LESSON #176), so after a pilot switch into J-space the old map and its YOU pin stayed under the message.
  • The status line names EVE location's J-space system by name (whName), not its ID.
  • In J-space with no known way in (itNoSysJ): Intel's line "You're in J… and where you came in isn't known (link it on the Wormholes tab), so no jumps and no alerts until then.", the same on the map, and in the System Analyzer's "My location".
  • Checks: tools/page_checks/dashless_search_check.py (made-up names for the shared form; the old map-search code run beside the new one for queries with a "-"; every box; the System Analyzer's list at 1440 and 390 px; the J-space lines and the empty map at both widths; 15 mutants). Info text: checked; none. Stored browser data: none.

Lesson for future models

  • LESSON #176: the hidden attribute loses to any rule that sets display. The check first read fb.hidden and passed; a screenshot of the state showed the old map still drawn. Assert the computed display, and look at a screenshot of each new state.
  • A plan's "one shared list" needs a scope per caller: the boxes that can only take systems with stargates would have been handed J-space names, and a short query like "j1" would have filled the map search's eight places with names the map then dropped.
