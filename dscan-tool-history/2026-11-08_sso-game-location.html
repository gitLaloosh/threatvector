Use my game location (SSO Phase 2)

Page 2026-11-08 · v2026.11.08.4

Why

  • Build queue 028, Project doc roadmap/sso-phase2-plan.md (the clickable prototype stays in the Project, the owner's choice at the review). Intel knew your system only from your Local log, which EVE writes when you change system: the game itself knows sooner. Phase 1 logged in without any permission; this is the first feature that asks for one.
  • The owner, on reading your ship: "if we can't see the ship AND the fit that you're actually in in-game, then dont deploy any feature/option that gives the impression that's what you're doing." So no ship permission is asked for, and nothing reads your ship.

What changed

  • Use my game location (Intel's settings, box 3 "You"): a checkbox. Without EVE's permission it shows a short box, Continue to EVE / Cancel. Back from EVE it turns on only if EVE gave the location permission (else SSO-07). While Intel runs, in the tab running it, as the character picked as You, the page asks EVE where that character is, no sooner than EVE's answer says it is fresh (about 5 s), slower when the app's share runs low, waiting when ESI says so. The newer of EVE's answer and the Local log wins; when they differ, an amber line shows both. Nothing about your location is kept: memory only.
  • The login is renewed in the tab while a feature needs it (about every 20 minutes). EVE refusing a renewal ends the login (SSO-06, Log in again); a refused call to ESI stops that feature and is never repeated by itself (SSO-08), since every refusal counts against ESI's error limit for everyone on the address.
  • The profile: "EVE permissions:" with a tag per permission and Manage on EVE's site ↗ (through the outside-link question). The button's line says "Also asks for: Location" when the switch is on. Log out turns the switch off and says the permissions ended with it: revoking the login takes Threat Vector off EVE's list of apps for the character (the owner's hand test).
  • Back from EVE's page without logging in (the owner's bug from 2026-11-07, "stuck in an evaluating login result state"): the EVE button is back at once, with "You came back from EVE's page without logging in, so nothing changed." LESSON #150.
  • Intel after the trip: if Intel was running when you left for EVE's page, it starts again when you come back (Authorize or Cancel); otherwise it stays as it was (the owner: "there is a switch for a reason"). If the folder needs your OK again, Allow reading shows and starts it. With sound on, a line asks for one click so the browser lets the sound play. Other tabs say "Intel is paused while the other tab logs in with EVE."
  • Alerts start unchecked for someone new (the owner: "if people dont notice that it's an option they might stop using the site just for peppering them with notifications. same with sounds"). Saved settings keep what they had.
  • Intel stopped reading: when the page loses the folder while Intel runs, one sound (Triple beep, or another built-in sound if yours use it), once, with sound on only.
  • A tab duplicated from a logged-in tab drops its copy of the login ("This tab was copied from another, so it's logged out here.").

The owner's hand test (dev app, 2026-11-08)

  • One permission comes back as a single string in scp, not a list (the page reads both). /location/ answered 200, then 304s while nothing changed.
  • A later login asking for nothing came back with no permissions: EVE gives a login only what it asks for, so the page asks for the features that are on every time.
  • Tokens last 20 minutes (expires_in 1199). /location/: Expires 5 s after Date; X-Ratelimit-Group char-location; X-Ratelimit-Limit 1200/15m; X-Compatibility-Date answered 2020-01-01 (the route's version; ours, 2025-08-26, accepted).
  • A forced renewal sent only grant_type, refresh_token and client_id, and EVE answered with the same refresh token; the checks carried on.
  • Duplicating a tab copies its sessionStorage; the copy said it was logged out and the original kept going.
  • Logging out in another tab logs this tab out through Phase 1's pilot rule, before any renewal.
  • EVE's authorized-apps list shows live logins only: Log out (the revoke) takes the app off it. The text that said EVE keeps the permissions was wrong and is corrected. The dev app and the live app are listed separately.

Kept in the browser

  • dscanIntel gains gameLoc (true or false). An older page ignores it; a newer page reading an older setting gets false. Intel's defaults for sound and notifications changed; saved values are read as before.
  • sessionStorage gains tvSsoTab (a random id per login); tvSsoPending gains want, from and intelWasOn. An older page reads the old fields and ignores the rest; tvSsoWho keeps its form.

Checks

  • New sso_game_check.py: a stand-in for CCP's login (keys made per run) and for ESI's location route (recording each request's headers; Expires, rate-limit headers, 401, 403, 429), the made-up Chatlogs folder kept across the trip to EVE. It covers the defaults, box 3 and its info panel, the scope asked for and read back (array and string), the profile's permissions and Log out, the headers sent, Expires and the slow-down, 429, 401, 403, the renewal (one at a time, the new refresh token kept first, invalid_grant, 429, an HTML 500), the login not being You, the tab without the lock, a duplicated tab, Back from EVE's page (a fresh load and from the cache), Intel after the trip (each case), the other tab's line, the stopped-reading sound and 390 px.
  • check_request_gates.py: the token, the compatibility date and X-User-Agent only in esiFetch's auth branch, which refuses anything but ESI first; ssoAccess only from esiFetch; a caller with the login must stop on a 401; ssoRenew listed.
  • The three checks that count alerts (intel_check, intel_one_tab_check, alert_sound_check) now start as a player who turned alerts on; alert_sound_check also checks the new default.
  • Mutants: 18 on the page, all caught (one needed the check to count forced redraws too); 6 on the request-gate lint, all caught. The "tab without the lock" case has no mutant: the checks run only from Intel's tick, which runs only while the tab holds the lock.
  • Every page check (the picker chose all: esiFetch is shared code), 47 min: two failures from this change, both checks' assumptions (the new sound default; a second target="_blank", now dropped), fixed and rerun; then the served-copy checks: 0 failed.
  • Page size: source 801,375 bytes gzipped (gzip -9; no ceiling); served 500,552, 299,448 under the 800,000-byte ceiling.

Lesson for future models

LESSON #150: a page that leaves for another site can come back from the back/forward cache exactly as it left. Keep "leaving" apart from "busy", undo it on pageshow with persisted, and on a normal load drop what was kept for the return and undo what was announced for it.
