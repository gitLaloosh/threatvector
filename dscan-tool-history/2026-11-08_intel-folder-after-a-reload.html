Intel: the chat-logs folder after a reload

Page 2026-11-08 · v2026.11.08.2

Why

  • Build queue 025, Project doc roadmap/intel-folder-permission-plan.md (no mockup, the owner's choice). The owner, logged into EVE with the folder chosen and a channel ticked, saw step 3 say "No Local log from the last 2 days" until he chose the folder again: "probably because i chose to only allow the file read on a per session basis? can we handle this behavior more cleanly?"
  • Chrome 122 and later asks again for a folder kept from an earlier visit ("Allow this time" lasts the visit; "Allow on every visit" stays), may take a one-time grant back while the tab is in the background, and asks only from a click (Chrome's post on persistent permissions; the File System Access spec). A folder restored from the browser's storage "is also likely to return 'prompt'" (the spec).

What changed

  • Step 1 by what the browser says (it.perm): needs your OK this visit: "Needs your OK this visit." with Allow reading (asks from the click itself) and Change…, and one short line "Pick Allow on every visit to skip this" (the plan's longer line was over the 40-character limit; the full explanation went into Intel's info panel, under "Reloads"). Blocked: "The browser is blocking this folder for this site." with Change…. Otherwise as before.
  • Steps 2 and 3 wait while the folder can't be read ("Waiting for the folder (1)"; step 2's saved ticks dimmed), and step 3 says "No Local log in this folder from the last 2 days. In EVE: Settings → Chat → Log Chat to File, then log in again." only after a read that found none.
  • Looks again by itself while the setup card shows: when the tab is shown again or the window gets focus, and every 15 s while the card can be seen. Nothing is read or drawn while the tab is hidden, and the card is redrawn only when the channels or characters found changed. So logging into EVE after choosing the folder shows up without pressing anything.
  • While Intel runs: a permission taken back (seen on focus, or when reading fails with NotAllowedError) shows INTEL-02 with Allow reading in the Intel card; the profile mark shows "not working" until it reads again. INTEL-02's text names Chrome's "Allow on every visit".
  • Nothing new is kept in the browser: the folder stays in Intel's IndexedDB store as before; it.perm isn't saved.

The stand-in keeps its own flags in window.name: flags kept in the page's storage didn't always survive the check's reloads (the page's own settings did; this was the stand-in only).

  • "Allow this time": a reload keeps the grant (Intel reads straight away). Only a new tab, a new visit, shows "Needs your OK this visit" with Allow reading, and Allow reading works from the click.
  • "Allow on every visit": kept across reloads, new tabs and choosing the folder again; the page can't undo it (only Chrome's site settings can), as expected.
