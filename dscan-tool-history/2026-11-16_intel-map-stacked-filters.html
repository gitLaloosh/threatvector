Intel map: filters that stack

Page 2026-11-16 · v2026.11.16.3 · build queue 058 · plan roadmap/intel-map-stack-plan.md, brief roadmap/map-filter-model-panel.md, mockup Claude outputs/stacked_filters_mockup.html

Why

  • The map could show one filter at a time. The owner wanted to combine them, for example the systems with a Threat Detection Array at level 3 whose security is between −0.5 and −0.3: "you can sort of stack them on top of each other". A panel review proposed a model, a prototype showed it, and the owner answered 21 questions (Q1-Q21 in the plan).

What changed

  • The filter column has three groups. Colour: Security, Jumps from you or Region, one at a time; pressing the one that is on turns colour off (plain grey, no number in the circles). Only: Security range and Within N jumps (new, each with a settings panel), Intel reports, Kills, Wormholes and Sov upgrades; any number at once, all of them must match, any pick inside one counts. View: Paths to you.
  • While an Only filter is on, the matches are bright anywhere on the map and a little bigger; the rest are dim, with no distance fade. Hostile and neutral rings, the alert glow and your pin never fade. Only the colour colours a dot: Kills and Wormholes no longer turn dots amber or lilac.
  • Soft colour: a system's colour is softened (mixed toward the background zoomed out, a tinted disc zoomed in) so rings, tags and labels stand out; a match keeps its full colour. Zoomed out, the alert glow is half its old size.
  • The legend gets a second line while an Only filter is on ("Only 3 match · security −0.5 to −0.3 · … level 3"), and the match chip ("3 match ›") steps through the matches, nearest first. It replaces 045's "N wormholes ›" chip.
  • Wormholes: with the filter on, the kept holes that match every Only filter get 045's bold mark, pulse and filled label; the others keep only the off-filter look.
  • Sov upgrades: a Level row of boxes 1, 2 and 3 in its panel; any ticked level counts, none ticked means any level.
  • A filter's settings button shows only while the filter is on or its panel is open (no longer on hover); switching a filter off shuts its panel.
  • Region's colours leave out the page's cyan, the kill amber and the wormhole lilacs.
  • The stack is kept between visits in a new localStorage key, tvMapStack. The older page never reads it; this page leaves tvSov as it was. Safe both ways.
  • Security shown on the map comes from one function, itMapSecT. The 19 low-sec systems whose security is stored as 0.45 now show 0.4 in the low-sec colour, as in the game (they showed 0.5 in the high-sec colour). See the lesson below.
  • Intel's info text, [Map] paragraph, rewritten for the new column (619 of 620 words). METHODOLOGY.md's Intel map section the same.

Lesson for future models (LESSON #170)

  • INTEL_MAP.sec holds CCP's security rounded to hundredths, and the map rounded that again to tenths in several places of its own. A system at 0.449 was stored as 0.45 and shown as 0.5, in the high-sec colour. The route planner was right only because it reads the band, which is worked out from the unrounded value, and nothing compared the two.
  • It was found by reading the plan's one UNVERIFIED row (how the game rounds negative security) against the stored data: counting the systems that sit exactly on an x.x5 and comparing the shown tenth with the band.
  • When a table stores a rounded value, work out the shown value in one function, send every reader through it, and check that function against every item. Better still, store the value people see: the generator has the unrounded one. The other x.x5 edge cases are a backlog item, because only the data can settle them.
