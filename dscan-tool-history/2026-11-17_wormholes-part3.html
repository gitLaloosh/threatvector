Page 2026-11-17 · v2026.11.17.2 · build queue 059 · plan roadmap/wormholes-part3-plan.md, mockups Claude outputs/wormholes_part3_mockup.html (scripts roadmap/wormholes-part3-mockup/) and Claude outputs/jump_bridge_lines_mockup.html (scripts roadmap/jump-bridge-lines-mockup/)

Why

  • The owner: "ability to copy/paste signatures from your in-game signatures list into a panel on the map.", then "signatures are IN a system so signatures should probably be come part of the system panel."; of a connection holding one ID for both sides: "this is a real issue"; "add a right click > remove all option that deletes any system not locked. add a verify step to this. also add a select all."
  • At the build review: "connections will have two IDs, one in each system as the connection is represented by signature in each system.", "maybe some kind of connector on each end that shows the signature ID on hover?", "could use a small version of the wormhole icon?"; and the jump bridge show/hide button "in 059", then "button defaults to on when jump bridges are enabled. no need for the line through it, just shows off state when they're turned off".

What changed

  • The System panel's order (whSumHtml): the summary, Class and Statics (they don't change), Connections, Signatures, then who's there and notes, Intel's reports, DOTLAN, Remove. A system that came from an import has one "shared" tag on its name line.
  • One list builder (whListHtml, with whLHeadHtml, whLThsHtml, whLRowsHtml, whLEditHtml, whLMultiHtml): the bar ("Selected: N of M" and its icon actions), sort headings (a button each, an arrow, aria-sort), rows in a grid (role="grid", aria-selected; a click selects alone, Ctrl / ⌘ / Shift-click adds, a phone tap adds, Space or Enter as Ctrl-click, the heading's box all or none), the in-place edit row, and the confirm piece (whAskHtml, focus on Cancel) used by every deletion in a panel and in the menus.
  • Signatures (whSigSecHtml, folding, kept in tvWhSecs): a paste box (open with nothing kept, else "Paste a new scan"), Read scan for the system in focus (a line when that isn't where you are); whScanRows reads the Probe Scanner's rows (every row with an ID: signatures, anomalies, structures; signal with . or ,; at most 150), counted, never guessed. Lazy update (the page's switch, off by default): a paste is the whole list, and anything it would remove is asked first (Remove them / Keep them). One-step Undo in memory. The list: the game's icon shapes redrawn in currentColor (WH_SG_ICON: wormhole, data, gas, relic, combat, ore; the cross and dot before a type shows; a dim placeholder for a kind with no shape), colour by the game's signal bands, short ages, sort kept in tvWhSigs.sort; Copy selected in the game's own copy format, Edit selected in place (one: ID, type, name; several: type), Delete selected asked first.
  • Connections (whCnListHtml, the same builder): one row per connection, this side's ID, the other system and this side's type, an EOL mark, age and →; colour by mass; Edit selected (one: this side's ID and type, life, mass, size, Drifter, the other side named; several: life and mass, "keep" by default), Delete selected asked first. Sort kept in tvWhSecs.cn.
  • Each side's signature ID (tvWhEnds, whEnd / whSide / whEndSet): the hole's own properties stay on the link in tvWhChain; each end has its own ID and type. A link's old single sig / type is "side not known" on both ends until a side gets its own, and is kept as it was. + Add's ID goes on the end in the linked system ("Sig ID in <system>"). A lazy scan that misses a connection's ID only marks that end (gone); the connection stays.
  • The map (whEndMarks): the mid-line label went; a small wormhole mark sits on the line just outside each system's box at each end with an ID; its hover (a tap on a phone) names that side's ID and type. Two marks close together merge into one whose hover has one line a side; an old ID shown at both ends is said once. No marks when zoomed far out.
  • Remove all and Select all on the empty-space menu (right-click, or press and hold on a phone): Select all (N); Remove all… asks in the menu ("Remove 12 systems and their connections? 3 locked stay."), then takes every system not locked with its links, marks, signatures and end IDs (whRemoveAll, one save, one itMapRefresh(true)). The System panel's Remove and the system menu's Remove ask first too.
  • Share beside + Add (.it-map-clr.wh-tb[data-wh-pop="share"], rule A by reuse): 046's two boxes, built by the same itWhShareHtml (now itWhShareHtml(w); Intel's markup unchanged) with Copy link added. The export (whChainExport): {tv: 'wormholes', v: 1, made, sys: [], chain: {sys, links, sigs}}, stable order, never positions, locks or where you are, notes and who's there only when ticked. The import (whChainRead, whChainMerge): known systems whose names match, known values only, limits counted; a preview, then Add to my map works it out again against the store as it is then: the newer edit wins per field, status and tag only into empty ones, signatures per ID by the later scan, nothing of yours removed or moved; a system you removed comes back. Copy link: #wh= + base64url(deflate-raw), at most 1,800 characters (WH_LINK_MAX_CH); opening one shows the preview and adds nothing until the press, the hash cleared. Intel's Import given a chain export points to the Wormholes tab.
  • The jump bridge lines button (Intel's map): button[data-im-z="jb"] under ⌖ in the zoom column (IT_JB_ICON, itJbBtnPaint), shown only while "Use jump bridges on the map" is on and pressed (on) by default; off hides the green curves and their hover (itJbHidden), never the counts or a route's bridge step; kept as jbHide in dscanIntel (missing = on). On a wide map Hide all routes moves left while it shows.
  • Storage, each safe both ways: tvWhSigs, tvWhEnds, tvWhSecs are new keys an older page never reads; tvWhChain keeps its form (its old single IDs kept), as do tvWhMarks and tvWhPanels; dscanIntel.jbHide is a new field an older page drops on its next save (the lines then show again).
  • Drawing cost (LESSON #120): the System panel's body is written only while it shows and only when it changed; it holds off only under a focused text field (WH_TYPING), so a press on a row redraws at once; ages change only when the body is written.
  • Info text: whmap rewritten from the plan (317 of its new cap of 320, check_subtext.py); its [Connections] line names the end marks. Intel's [Jumps and your system] says the bridge button hides the curves (670 of 670). The legend: "select all or remove all".

Where the build differs from the plan

  • The map's IDs are marks at each end, not text a third of the way along (the owner at the build review, above).
  • "shared" is one tag on the name line, not a mark beside each field.
  • Share's boxes start shut, opened by 046's own toggles, as on Intel's list.
  • #wh= is read by the Wormholes module (whLinkOpen, at start and on hashchange), not sharedKillLinkInit.
  • The export waits for system names only when the chain has k-space systems (whNamesFor), so an all-wormhole chain exports offline.
  • The jump bridge lines button rides with this build (the owner: "in 059").
