J-space statics known the moment you enter a system

Page 2026-11-19 · v2026.11.19.1 · build queue 061 · plan roadmap/wh-statics-plan.md, mockup Claude outputs/wh_statics_mockup.html (scripts in roadmap/wh-statics-mockup/)

Why

  • The owner: "i need you to find a way for us to know what a j-space systems's statics are when the user enters one. i know what wanderer does it." CCP's data doesn't list a system's statics; until now you typed them.
  • His picks (Q1-Q8): Wanderer's file as the source; shown "similarly to the way they are in wanderer" in this page's own style; checked with the game data twice a day; the map box in class order, mass and lifetime on hover, statics first when typing a type; a small mark, yours replace; the info text cap 340; CCP's numbers on hover.

What changed

  • The table (INTEL_WH_STC, its own block after the wormhole table): every one of the 2,604 wormhole systems' statics from Wanderer's community list (wanderer-industries/wanderer priv/repo/data/wormholeSystems.json at 4d4a035, MIT), written only by tools/gen_wh_statics.py, which checks every record first (the same systems as INTEL_WH, matched by ID; 1-3 codes each, all in IT_WH_TYPE; no K162) and keeps Wanderer's licence. It names the file, the commit and its sha256, and the system list it follows (n, and of, FNV-1a of INTEL_WH.sys): whTable uses it only while both match. 853 bytes gzipped.
  • Yours, else the list's (whStcOf, the one place that decides): the System panel's chips and the map box show what you typed, else the list's. The list's are never saved, shared or exported (tvWhChain unchanged). Under the chips the page's dim note, as Class has: "from the community list (Wanderer) · type your own to replace them" or "typed by you" (whStcNoteHtml). The field stays empty for the list's; typing replaces them, clearing brings them back, also while typing (whStcPaint).
  • Class order (whStcSort, WH_STC_ORD): chips and the map box by where they lead, in CCP's class-number order (C1-C6, highsec, lowsec, nullsec, Thera, shattered, Drifter, Pochven), typed statics too (stored as typed).
  • The hover (whStcLifeTxt): a chip's title adds CCP's numbers for the type, "up to 16 h · 2,000,000 t in all · 375,000 t per jump" (and "regains N t" where CCP has one), from IT_WH_LIFE, written by tools/gen_wh_table.py (attributes 1382-1385).
  • Suggestions (whTyOptsHtml, the browser's own list): the connection editor's Type field offers the system's statics first, then K162, then every other code; + Add's type field the "Linked to" system's, following that choice (whAddTyList). Typing anything is still allowed.
  • Updates: a new job in .github/workflows/jump-table.yml, wh-statics, twice a day: Wanderer's newest commit's file through gen_wh_statics.py; a pull request on wh-statics/<commit> when the statics changed (or the page's system list moved under them), listing each changed system. It also writes the field names of CCP's J-space system records into its run's summary (a report only), to settle whether CCP's own data has statics.

Where the build differs from the plan

  • The statics are their own block, INTEL_WH_STC, not a field of INTEL_WH (the owner at the build review, "go with your recommendations"): tools/jump_table_update.py compares the whole of INTEL_WH with its rebuild, so a field in it would have made every scheduled run open a pull request that drops it; and a field carried over would pair systems with another system's statics if CCP's list of wormhole systems changed. jump_table_update.py is unchanged.
  • The workflow job runs beside the jump-table and game-data jobs, not after them (order doesn't matter: each opens its own pull request). It reports CCP's J-space fields in its summary (the review's R2), since neither CCP's site nor ESI could be reached from the build session.
  • The chain's lint (gen_wh_statics.py --check) checks the block on its own and compares it with Wanderer's pinned file only where GitHub's raw files can be reached; the Action compares it twice a day.
  • + Add's suggestion list follows "Linked to" (the plan named only "when Linked to names a J-space system"): a k-space or "nothing" link offers K162 first.
