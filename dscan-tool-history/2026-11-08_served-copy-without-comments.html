The site serves the page without comments

Tools 2026-11-08 · page unchanged (after v2026.11.08.2)

Why

  • Build queue 027, Project doc roadmap/page-publish-plan.md (no mockup: nothing users see changes). The page was 788,861 bytes gzipped, 11 KB under the owner's 800 KB line ("At 800 KB", 2026-11-03), and SSO Phase 2 would cross it. His answer then: a publish step that strips comments from the copy the site serves, not cutting features; "GitHub Actions deploys it"; the ceiling applies to the served copy ("confirmed").

What changed

  • tools/publish.py makes the served copy: every file git tracks (what the site served from the branch), less dotfiles and .github/, with index.html stripped of comments and its CSP hash rewritten. It checks the result before writing anything and prints both sizes. Measured: 788,861 → 492,223 bytes gzipped (−38%).
  • The script's comments: acorn, not terser. The plan named terser; this sandbox can't reach the npm registry, so terser couldn't run here and the served copy couldn't be tested before a pull request. The owner picked "acorn, kept in the repo": acorn 8.18.0's dist/acorn.js (MIT, one file, no other packages) is copied into tools/publish/ with its licence; the workflow checks the copy against npm's on every run. tools/publish/strip_js.js reads the script's tokens and copies each one's text as is; what lay between two tokens becomes one line break if it held one (so automatic semicolons stay where they were), else one space. Then the tokens, and whether a line break comes before each, are compared with the source's one for one. Strings, template literals and regular expressions are tokens, so nothing inside them can change.
  • CSS and HTML comments by a small scanner (strings and url(...) skipped); a comment alone on its line takes the line with it. Outside the script, the ids, data-* names and tags must match a second, naive reading of the source.
  • .github/workflows/pages.yml: on every merge to main and by hand, check acorn, run publish.py, upload and deploy (configure-pages@v5, upload-pages-artifact@v4, deploy-pages@v4, as GitHub's docs give them).
  • The site's two PNG icons were never committed. .gitignore ignores every *.png except a list, and favicon-32.png and apple-touch-icon.png (v2026.11.07.4) weren't on it, so the site has served neither since: browsers fell back to the SVG icon, and a phone's home screen got no icon. Found because the served copy failed csp_check's icon test; both are now committed.
  • Markdown files: deploying from the branch ran Jekyll, which also served each .md file as an .html page; the workflow publishes the files as they are, so those are now served only as .md. Nothing on the page links to them.
  • Rules: CLAUDE.md step 6 (both sizes, the ceiling on the served copy, run_checks.py --served before a pull request) and a paragraph on the served copy; run_checks.py --served [--all]; run_regression.mjs --served (the PYFA CORE lock reads comments, so it stays on the source); the publish self-test among the fast lints; NOTICE.md credits acorn; the newest backlog file is now dscan-backlog-3.
