Checks that don't depend on EVE's downtime

Tools 2026-11-15 · page unchanged (after v2026.11.15.2) · the backlog bug "outage_check fails between 11:00 and 12:00 UTC"

Why

  • The page counts 11:00-12:00 UTC as EVE's daily downtime: from 10:56 the strip says it starts soon, and in that hour a failing ESI is called "EVE's daily downtime" instead of "EVE's ESI is down". The line itself shows only while ESI fails and goes at the first answer, however long the downtime is; the hour only picks the words.
  • outage_check's ESI-down cases ran on the real clock, so any run between 11:00 and 12:00 UTC failed 5 of them, on an unchanged page too (051's run started 11:14 UTC). feed_down_check and intel_kills_check expect an empty strip and could fail in the 4 minutes before 11:00.
  • The owner, offered fixing the check only or the page's wording too: "go with option 1" (the check only; the page keeps its hour).

What changed (tools only)

  • tools/page_checks/off_downtime.py (new): a copy of the page whose downtime hour is 12 hours from the run (the page's own code; only SYS_DT_HOUR moves). It stops with a failure if the page's line const SYS_DT_HOUR = 11, changes, so a moved hour can't pass unnoticed.
  • outage_check moves the hour in its page copy, and its downtime cases set the page's clock 4 minutes before and 2 minutes after that hour (the words still say 11:00 UTC).
  • intel_kills_check opens the moved-hour copy; the checks built on its start get it too (feed_down_check, close_buttons_check, intel_fleet_check, html_escape_check, intel_filters_check, intel_guard_check, intel_layout_check).
  • Proof: a copy of the page that thinks it is in the downtime hour now (its hour stretched to 10 hours): the old outage_check fails on it, the new one passes.
  • wormhole_menu_check (051's): it read origin/main as "an older page (part 1)", so it failed on every run after 051 merged (found by this delivery's run). It now reads the part-1 page at a fixed commit, 9459b35 (v2026.11.15.1).
  • The page, .github/workflows/ and what browsers keep: unchanged.

Not in this delivery

  • The page's words: an ESI failure that starts later in the hour (say 11:40) is still called the downtime (option 2, not chosen).
  • The open bug "Downtime notice stays up after EVE is back": its cause is still unknown (the line follows the status check, not the clock).

Lesson for future models

LESSON #168: a check that reads the real clock passes or fails by the time of day it runs. Move what the page does at a set time away from the run (or set the page's clock), and prove it on a page that thinks it's in the window: the old check fails there, the new one passes. The same goes for a branch: a check that needs an older page names its commit, never "main", which moves.
