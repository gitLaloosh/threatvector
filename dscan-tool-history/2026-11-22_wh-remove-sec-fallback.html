Why

  • A bug the owner recorded 2026-11-21: "record the following bug related to removing a system from the wormhole tab: content hidden by bottom of the map." The system menu was placed once when it opened; its Remove question made it taller and nothing placed it again, so Remove and Cancel went under the map's bottom edge.
  • A request the same day: "ability to select a group of systems exists but not the ability to remove all selected systems. when multiple are selected, right click > delete (can we have this work with the delete key?) should delete everything that's selected (with verification prompt of course)." At the review: the group menu's other items act on "The one right-clicked (Recommended)", the Delete key's question shows "Beside last-picked system (Recommended)", "No mockup (Recommended)".
  • 063's data pull request (#77) brought INTEL_MAP.secT and took out sec and band, so the page's fallback for a table from before 063 went with the next page delivery (the owner, 2026-11-21: "that delivery removes 063's fallback").

What changed

  • Both Wormholes menus are placed by one helper (whMenuPlace): no taller than the room inside the map and on the screen (they scroll), moved up to fit. whMenuReplace places a menu again from where it was opened whenever its content changes (the Remove question, the group's question, Remove all's question, Copy the name's fallback field) and scrolls the question into view.
  • Removing the selection: a right-click (or press and hold) on a system inside a selection of 2 or more makes the menu's Remove "Remove N selected…" (whGroupOf); it asks Remove all's kind of question for the selection, naming locked systems that stay (whGroupAskHtml). The menu's other items still act on the system right-clicked. Outside the selection the menu is as before. One remover for any list of systems, whRemoveIds (one save, one repaint, one Intel map refresh); Remove all now calls it. The selection is cleared after.
  • The Delete key (and Backspace): with the map focused and no text field, menu, pop-up or panel in use, the selection's question (or a single selected system's own) opens in the system menu under the system picked last (M.last, set by a click or Shift-click; whDelKey). Nothing is removed until Remove is pressed.
  • 063's fallback taken out: itMapTable needs secT (a table without it is no map), itMapSecT returns the table's tenth, itRpBand reads only the shown tenth's band, itMapBand and itSecTab's secT test are gone. The checks: check_sec_shown.py refuses a page without secT and any read of the old columns (new mutants: the old sec read again, itMapBand brought back); check_jump_table_update.py drops its case of a page from before 063; intel_map_look_check, intel_map_stack_check and route_planner_check drop their fallback cases (the route check's made-up graph now carries tenths; a new mutant moves the band's 0.5 line).
  • Info text: whmap [Moving around] now says a box-selected group can be moved or removed together (Delete); 400 of its 400 words.
  • Checks: new tools/page_checks/wormhole_remove_check.py (the question inside the map at 1440 x 700 and 390 px, opened low and at the top; Remove all's question; the System panel's own; the selection's Remove with a locked system; the tag on the right-clicked system only; Delete and Backspace; Delete typed in the Add box or the tag field; 8 mutants). wormhole_menu_check's three mutants on lines this change moved point at the new lines.
