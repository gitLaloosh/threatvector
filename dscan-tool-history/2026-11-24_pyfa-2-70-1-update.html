What changed in pyfa (v2.70.0 → v2.70.1)

  • Synchronizer rigs (41b0629, a2c7b8e): each faction module's own effect (Effect12963–12966, 12989–12993; type offline, a new run time earliest) adds its rigSet…Module to every fitted Synchronizer's rigSet…Bonus; the rig's counting effect reads its own rigSet…Bonus. So every matching module counts, offline included, and a mutated one never does (it is its abyssal type in pyfa, which has no such effect).
  • Rigs and subsystems first (b05457a, "Fix edge-cases around sansha synchronizer"): fit.py runs them before other modules in each pass.
  • The 'Vigilant' Drifter modules (820d0d8): Effect13048–13051 now change the module's own attribute, which its ordinary effect reads (the Overdrive Injector's implantBonusVelocity ×3; the Shield Boost Amplifier's shieldBoostMultiplier ×3; the Drone Navigation Computer's speedFactor ×3; the Cap Recharger's capacitorRechargeRateMultiplier forced to 0.64). Before, they changed the ship, the boosters and the drones directly.
  • CCP data 3682781 → 3724492 (b79cd90, 820d0d8): the Vengeance's shipBonus2AF 3 → −5 (launchers 25% faster at Amarr Frigate V); 47 boosters renamed "Expired …" and unpublished; eight Chinese ship names; Supply Depot and text changes the page doesn't read.
  • Not modelled by the page, so nothing to do: darkness weather's stacking penalty (5f0190c), a conversions file (6a1e868, two renamed drones; the page keeps no rename list), pyfa's saved-fit events and matplotlib (30a4b0a, ac23acc, 5af4b95).

The first step: pyfa_update_check.py --run against v2.70.1, before any change

17 steps failed: the Synchronizer table (its guard: "reads a rigSet...Bonus attribute"), the resist generator (unexpected value expression (-a:rigSetDreadGuristasBonus)), the implant, projected, speed, module-state and Intel tables, the effect-table audit, the golden-fit data, and five comparisons with pyfa (resists 3 fits, missile range 1, every golden fit 5, application 4, projected 6). All the rest passed. Every comparison failure but one was the oracle's (below); the other was the Vigilant Drake (cap recharge 309.4 s against pyfa's 300.0).

Two gaps in our own tools, fixed first

  • The oracle (tools/pyfa_fit_oracle.py) ran only early, normal, late, so it never ran the Synchronizer writers and counted no module: every Synchronizer golden "differed" from pyfa by the oracle's own figures. It now runs earliest first and sorts rigs and subsystems first, as v2.70.1's fit.py does. After the fix only the real changes differed. LESSON #181.
  • The removed boosters (pyfa_sde.pyfa_removed_types) looked only at published boosters. pyfa's db_update.py keeps only published rows, with its own name overrides ("Expired …" off, "AIR … Booster" on). Regenerated as it was, PYFA_REMOVED_IMPLANT_IDS would have lost all 47 expired boosters, which pyfa can't load. Now pyfa_db_published ports those rules: the list holds every implant and booster pyfa lacks (1,292; none of the 177 before dropped), and gen_implant_table.py's pool takes pyfa's view, which brings in the 16 "AIR … Booster" boosters CCP leaves unpublished (three booster effects: 1635, 272, 4967).

What was done

  • Synchronizers (PYFA CORE synchronizer-rigs): gen_sync_table.py rewritten for the new model, SYNC_WRITER_EFFECTS (9) and SYNC_RIG_EFFECTS (9), from pyfa_effects.sync_effects; it refuses v2.70.0's shape, a writer that isn't offline / earliest or whose filter isn't exactly the Rig Synchronizer types, a writer on an abyssal type, and any other pyfa effect writing a rigSet… attribute. pyfaSyncRigTypes: the rig's own bonus plus every faction module copy, in any state, less a pasted copy marked mutated (parseEftFit → parsed.mutated → options.mutated, through the Fit Analyzer's input and chgEngineOptions). gen_resist_table.py skips both kinds. DEVIATIONS.md: both TEMPORARY Synchronizer rows deleted.
  • The 'Vigilant' modules (new PYFA CORE self-active): tools/gen_self_active_table.py writes SELF_ACTIVE_EFFECTS (13048–13051; it asserts each attribute is read by a passive of every carrier and changed by nothing else; Effect7012, the Assault Damage Control burst, has the same shape and stays in the resist calc). pyfaSelfActiveDogma gives a module's active copies their own attributes; the engine's selfActiveParts splits the module where its passives are read: the capacitor and module-attribute tables, the speed calculation and the drones' and fighters' attributes. The old rows went: 13048 (SPEED_EFFECTS), 13050 (PROJ_DRONE_EFFECTS), 13049 and 13051 (the hand-written cap and repair tables). gen_speed_table.py called every self row "overheat"; it now says which are overheat, self-active or a Synchronizer's.
  • A 035 bug found on the way: 035's 13049 row sat in SIEGE_FAMILY_REMOTE_REP_EFFECTS, read only for siege modules, so the active amplifier's bonus never reached the page; the Drake's shieldRepSustainedDps pin (86) was the tool's own number, because compare_fit_stats.py left shield reps out with an amplifier. Lessons for future models

  • #181 When pyfa adds a run time or changes the order, the oracle must too: a mismatch on every fit of one mechanic is a reference problem until shown otherwise.
  • #182 A pin taken from the tool where the comparison skips that stat checks nothing; a row added to a hand table must land in a table the engine reads for that module.
