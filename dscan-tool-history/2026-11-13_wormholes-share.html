The Wormholes list's Export and Import

PageIntel 2026-11-13 · v2026.11.13.2 · build queue 046 · plan: roadmap/wormholes-export-import-plan.md · mockup: Claude outputs/wormholes_share_mockup.html

Why

  • The owner, 2026-11-12: "plan a change to the wormholes list panel that allows you to export from and import to your wormhole list. import should have de-dupe/merge logic to ensure that any pre-existing holes are only added to and not duplicated or lose data."
  • His decisions: export copies JSON only ("it's just json going to the clipboard"), in a box inside the list; fixed Export / Import labels with Intel's chevron; names replaced with "<a pilot>"; your removals win unless the report is newer; what you entered is never overwritten, worked out from the raw lines ("compare the raw report text shapes"); a repeat is one line with a count.
  • At the build review: an imported hole acts like one of your own Intel reports ("i think so"), and its hover says it's from a shared list ("I agree").

What changed

  • Export (itWhExportObj): the list as {tv: 'wormholes', v: 1, sys}, only systems inside the keep setting, stable order; each line redacted default-deny by Intel's own reader (itWhRedact: a word it places stays, anything else is one "<a pilot>"); hand lines rebuilt from what they set (itWhSetText); no reporter, removals or settings. Shown selected in a read-only box with Copy (Ctrl+C line if the browser refuses).
  • Import (itWhImportRead, itWhImportPlan, itWhMergeOne, itWhDerive): checks everything (format, version, 256 KB, systems and names, times, IDs, types, details, limits); a preview first ("Adds … · adds to … · already have … · kept yours for …", "Skipped: …"), then Add to my list or Cancel. Lines are matched by their redacted text; details are worked out again from all lines (your own lines as Intel does today; a shared line never beats a value you set by hand, a newer one shows as "!"); a value with no line is kept; removals win unless newer; the 10-line cap keeps lines that decide a detail.
  • Repeats: the same words again later are one line, "×N" (your own Intel lines too).
  • Shared holes act like Intel's reports; their badge, map hover, list row and ID titles say "from a shared list, reported by <a pilot>".
  • Info text: intel [Map] "its list edits and shares them" (410 of 410 words); METHODOLOGY.md's Intel section has the detail.
  • Stored: new fields only (n, k: 'shared', via on lines; note, via on IDs; via on entries); no request, no new error code.

Checks

  • New wormhole_share_check.py: two browsers. A's lines through Intel's made-up folder (a pilot, a ticker in brackets, a two-word name in wormhole lines), one hole added by hand; its export leaks none of them and keeps the systems, ships, IDs, types and detail words; the round trip into an empty B; importing again changes nothing; B's own list merged (your hand value kept with a "!" note, a part completed, a removed ID and system kept out by older reports and brought back by newer ones, a value with no line kept, the cap, one line per report with the larger count, someone's hand-added hole); bad input refused; Cancel; the boxes, focus, Esc and 390 px; five mutants.
  • The mockup's own test_xi.py again from main 60d75f1: 82 checks, all passed.

Lesson for future models

  • LESSON #164: the mockup's redaction split a line at each "<a pilot>" and read the pieces alone, so a shared line exported again lost its signature words (the piece after the placeholder had no "wh"). The round-trip check caught it; the line is now read whole, the placeholder one word the reader can't place.
