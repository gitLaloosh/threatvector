## 5. Per-end signature IDs (the bug)
**P9 The model.** A connection keeps the hole's own properties where they are (life, mass, size, Drifter, times, in `tvWhChain`'s link), and gets **one signature ID and type per end** under a new key **`tvWhEnds`** `{v: 1, links: {"<a>-<b>": {"<sysId>": {sig, type, gone?}}}}` (the key is `whLinkKey`; `gone` = when that end's ID was last missing from a lazy-update scan). Not in `tvWhChain` (whRead's rebuild). Safe both ways: an older page shows the link's old single `sig` / `type` as today and never reads `tvWhEnds`; this page drops entries whose link no longer exists.

**P10 Today's single `sig` / `type`** (set by + Add, the Connections list or an import) can't say which side it was on. It stays in `tvWhChain` as **"side not known"**: shown on both ends with "(side?)" in its hover, used for matching on either side, until an end gets its own ID; from then on that end shows its own. This page never writes the old field again except to keep what's there, so a revert loses nothing.

**P11 Where each end's ID comes from:**
- The **Connections list** in a system's panel (P22): its row shows **this side's** ID and type; Edit selected sets them ("Sig ID here", "Type here"); life / mass / size / Drifter stay shared (one hole). - **+ Add:** the signature ID and type typed are the end in the "Linked to" system (where you scanned it), as the form reads today (the field's label says so: "Sig ID in <linked system>").
- **A paste** never sets a connection's ID (P7: it can't know where a hole leads); it only matches and marks `gone`.

- **The map line:** each end's ID drawn near its own system (a third of the way along the line), the type after it; the old single label only while the side isn't known. (Built differently: marks at each end, see "Built".)

**P12 Matching** (P7, P5): a scanned row in system S matches link L when S is one of L's ends and the ID equals that end's own ID, or a part of it that fits only that one; failing that, L's "side not known" ID.
